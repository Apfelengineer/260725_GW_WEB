# JSONからの予定一括登録

管理者モードで、画面上部の「JSONから予定を取込」を選択します。

1. JSONファイルを選び、「内容を確認する」を押します。
2. 全件の検証結果、新規登録件数、登録済み件数、先頭20件までの内容を確認します。この段階では予定は追加されません。
3. 「○件を登録する」を押します。
4. 登録後に予定表を再読み込みし、予定が残っていることを確認します。過去・未来の予定は、その日付へ移動して確認してください。

## 取込用JSONの例

```json
{
  "schedules": [
    {
      "id": "legacy-000001",
      "memberId": "m6",
      "date": "2026-11-10",
      "endDate": "2026-11-10",
      "start": "09:00",
      "end": "12:00",
      "timePreset": "morning",
      "title": "機器利用予約",
      "location": "電波暗室",
      "category": "機器利用",
      "memo": "移行した予定",
      "private": false
    }
  ]
}
```

ファイルはUTF-8のJSON、最大1MiB・5000件です。予定の配列だけを記載した形式（`[{...}, {...}]`）も受け付けます。

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | 任意 | 元システムの予定ごとに一意で、次回も同じ値となるIDを推奨。最大120バイト、空白・制御文字不可。省略時は内容から自動生成。 |
| `memberId` | 必須 | 登録先ユーザー・試験室の内部ID。社内入口の3桁IDとは別。取込画面の「ユーザーID・予定種別を確認」で参照可能。 |
| `date` | 必須 | 開始日。実在する日付を`YYYY-MM-DD`で指定。過去日も可能。 |
| `endDate` | 任意 | 終了日。省略時は開始日。開始日以降の日付。 |
| `start` | 必須 | 開始時刻。`00:00`〜`23:59`。 |
| `end` | 必須 | 終了時刻。`00:00`〜`24:00`。同日予定では開始時刻より後。 |
| `timePreset` | 任意 | `custom`（省略時）、`all-day`、`morning`、`afternoon`。 |
| `title` | 必須 | 空ではない予定名。最大1000バイト。 |
| `location` | 任意 | 場所。省略時は空文字。最大1000バイト。メモとは別に保存。 |
| `category` | 必須 | 登録済みの予定種別の名称と完全一致する文字列。 |
| `memo` | 任意 | メモ。省略時は空文字。最大20000バイト。 |
| `private` | 任意 | `true`または`false`。省略時は`false`。文字列の`"false"`は不可。 |

`timePreset`を指定する場合、時刻も以下へ合わせてください。任意の時刻は`custom`を指定します。

| 時間帯 | start | end |
|---|---|---|
| `all-day` | `00:00` | `23:59` |
| `morning` | `09:00` | `12:00` |
| `afternoon` | `13:00` | `17:00` |

## 登録のルール

- **既存の予定は削除・上書きしません。**
- 同じID・同じ内容の予定は登録済みとして除外します。ID省略時も、同じ内容からは同じIDを生成します。
- 同じIDで内容が異なる場合、またはファイル内でIDが重複する場合は全件中止します。
- IDが異なれば、内容が同じでも別予定として追加されます。元システムのIDを固定して使用すると再取込時の重複を防ぎやすくなります。
- 不正な日付・時刻、未登録のユーザー・予定種別などが1件でもある場合は全件中止し、該当する件数位置と理由を表示します。
- ユーザー・試験室・予定種別は自動作成しません。先に管理画面で登録し、その内部ID・名称へ移行元データを対応付けてください。
- 内容確認後に別の変更が保存された場合、古い確認結果では登録しません。画面の再試行を行い、内容確認をやり直してください。
- 登録はDB取引で一括実行し、操作履歴に記録します。公開カレンダー用JSONの再生成対象にもなります。カレンダーを停止していても予定の取込は可能です。

## バックアップJSONを使う場合

本システムの`{"payload": {...}, "sha256": "..."}`形式も読み込めます。整合性を検証し、`payload.state.schedules`内の予定だけを取り込みます。

**ユーザー・予定種別・アカウント・権限・管理者パスワードは取り込みません。** 復元ツールと異なり、新しいDBへの置き換えは行わず、現在のDBへ予定を追加します。バックアップに含まれない予定を復元する機能ではありません。

元のバックアップファイルは機密情報を含むため、GitHubや公開フォルダへ置かないでください。アップロードしたファイルをサーバー上の公開フォルダへ保存する処理はありません。

実データの初回移行前にはDBをバックアップし、少数のテスト予定でユーザー・種別・日付・時刻の対応を確認してください。
