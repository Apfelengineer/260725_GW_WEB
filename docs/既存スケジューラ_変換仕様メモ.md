# 既存スケジューラの変換仕様メモ

2026年11月8日：提供ファイルの解析と利用者からの補足に基づく整理。オフライン変換ツール自体は未作成。

## 保存単位

- ユーザーごとにディレクトリを分け、月ごとに`YYYYMM.sch`と`YYYYMM.dtl`を生成する。
- 提供サンプルはCP932で解読可能、改行はCRLF。固定位置は文字数でなくバイト数。
- ユーザーはファイル内ではなく、変換時に元ディレクトリとKPTCの内部ユーザーIDを対応付ける。

## schの項目（先頭を0としたバイト位置）

| 位置 | 内容 | 変換方針 |
|---|---|---|
| 0〜1 | 開始日の日 | ファイル名の年月と組み合わせて`date`へ。 |
| 2〜6 | 開始時刻 | `start`へ。開始・終了とも空欄なら終日。片方だけ空欄は確認対象。 |
| 7〜11 | 終了時刻 | `end`へ。終日は`00:00`〜`23:59`、`timePreset: "all-day"`。 |
| 12〜25 | 分類 | KPTCの予定種別名へ対応付け、`category`へ。 |
| 26〜29 | 表示形式・通知時間 | 利用者指定により無視する。期間として扱わない。 |
| 30〜69 | 件名 | `title`へ。 |
| 70〜109 | 場所 | 新設した`location`へ。メモへ混ぜない。 |
| 110〜112 | 詳細メモ番号 | dtlの同じ番号のメモを`memo`へ。 |
| 113〜114 | 複数日の期間 | 開始日を含む日数。`02`なら開始日＋1日が終了日。 |
| 115〜128 | 色コード | 利用者指定により無視する。 |

終了日は開始日に「期間−1日」を加えて計算する。月末・年末も暦に沿って計算する。提供ファイルでは行の末尾項目が省略されるため、短い行を異常と即断しない。期間欄の省略は単日とする想定だが、`00`・不正な値の扱いはツール実装時に確認する。

利用者の補足により、以前の「113〜114は文字装飾かもしれない」という推測は撤回する。例としてサンプルのテスト２は4月6日〜7日、テスト６は4月19日〜22日、テスト７は4月23日〜24日と解釈する。

## dtlと残る確認点

- 先頭の3桁番号をschの詳細メモ番号へ結び付ける。
- メモ本文内のカンマが改行を表す可能性があるが、本文に実際のカンマ・引用符を入力した場合の保存規則は未確認。
- 同一予定の月またぎ時に、翌月ファイルへ同じ予定が再収録されるかは未確認。重複排除の仕様を決める際に確認する。
- 元データに安定した予定IDが見当たらないため、ユーザー・月・元レコードなどを使ったID生成と再変換時の重複防止が必要。

元のデータファイルは変更せず、変換結果と警告を別ファイルへ出力する方針とする。
